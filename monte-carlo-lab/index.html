The model (one month)

Rides per scooter R ~ Normal(180, 50)
Demand (rides) D ~ Normal(20,000 − 1,500 × price, 2,000)
Cost per ride c ~ Uniform($2, $3)
Unavailable scooters U ~ Discrete(0, 5, 10, 15, 20, 25 with probs 0, .1, .2, .3, .2, .2)
Rides served = MIN(D, (scooters − U) × R)
Profit = rides × (price − c) − $20,000 fixed cost

From RAND() to a random draw

Every random input starts as a uniform number between 0 and 1. Reading that number on the vertical axis and across the distribution's cumulative curve gives the draw. This is what NORM.INV(RAND(), …) and RiskNormal do.

Cumulative probability (CDF)Your RAND() and its drawHistogram of draws so far
0.730

Why it works. A RAND() value lands in any slice of [0, 1] with probability equal to the slice's width. The CDF is steepest where the distribution has the most probability, so many RAND() values map there.

Drag the slider: values of RAND() near 0.5 give draws near the middle; values near 0 or 1 give the tails. Then draw 500 and watch the histogram take the distribution's shape.

How many iterations are enough?

The running average of profit after each iteration. Early on it jumps around; it settles as iterations accumulate. The shaded band is the 95% confidence interval for the true mean.

This run95% confidence bandEarlier runs
Hover over the chart to read the running mean.

The square-root rule. The band's half-width is 1.96 × std dev ÷ √n. Ten times more iterations make it only about 3 times narrower; halving it takes 4 times more.

Seeds. A run is a sequence of RAND() values. Fixing the seed replays the same sequence, so “run again, same seed” lands exactly on top of the last line. In @RISK: Simulation Settings → Sampling → fixed random seed.

Comparing decisions: which price?

Mean profit for each price from $6 to $11. Same random numbers for every price compares the prices on the same set of months, like RiskSimtable with a fixed seed. Fresh random numbers give each price its own months.

Best price in each re-run

Why same random numbers? With fresh numbers, a price can win just because it happened to draw good months. Using the same months for every price removes that luck from the comparison, so the curve is smooth and the ranking is much more stable. If the winner still alternates between two neighbors, those prices are practically tied.

@RISK: put =RiskSimtable({6, 6.5, …, 11}) in the price cell, set # Simulations to 11, fix the seed, and compare RiskMean(profit, k).

Fitting a distribution to data

Instead of assuming Normal(180, 50), use data on rides per scooter. Each candidate distribution is fitted by maximum likelihood and ranked by AIC (lower is better), as in @RISK's Distribution Fitting.

Data points

AIC = 2 × (number of parameters) − 2 × log-likelihood. It rewards fitting the data and penalizes extra parameters. Only differences matter: a gap under about 2 means the fits are practically tied.

Try 20 data points and click New sample a few times: with little data the ranking flips. With 300 it settles.
